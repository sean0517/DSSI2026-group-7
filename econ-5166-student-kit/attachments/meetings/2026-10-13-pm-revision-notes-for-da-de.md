## 一、我這次改了什麼

**第 1 節（研究問題、動機、資料來源、方法）**

- 研究問題收斂成「正賽開跑前預測是否進前三名」，不做排位賽。開頭先點出已知與未知：既有研究說名次約九成由車隊決定，我們要問剩下的部分能不能在賽前辨識。
- 研究動機重寫，主軸四句話：九成由車決定、同車不同人結果不同、「人」的部分沒被量化沒被預測、所以我們來測。案例留三個（2023 Red Bull、2024 摩納哥、2020 沙基爾），人名只剩 Pérez。
- 補了文獻缺口的論述，三條線各一句並附引用，`references/` 新增 9 個檔案（1 份文獻地圖 + 8 篇筆記），文末新增參考文獻清單。
- 資料來源每項補「拿到了沒」與「限制」：Kaggle 已取得 14 個 CSV；FastF1 只到 2018 年、尚未下載、列為備用；Open-Meteo 尚未串接、取得的是實際天氣不是預報。
- 研究方法明訂預測時點為「排位賽結束後、正賽開跑前」。第二階段特徵清單改成和研究問題一致的六類，分群標籤統一叫 `style_cluster_prev`，新人另設「無前季資料」類別。
- 第一階段三個特徵算法改成可執行版本：安全車圈用「慢於該車手該場中位數 10% 以上」排除；輪胎衰退改成 stint 內圈速對圈數的斜率；名次推進改成減隊友同值、用 `positionOrder`。
- 訓練測試切分定為 2012–2022 訓練、2023–2024 測試；兩版 AUC 差距用 bootstrap 估信賴區間，刪掉「顯著」。

**第 5 節（上次 meeting 定為我負責）**

- 重寫為九點。保留原本的類別不平衡、賽車性能、分群解釋性、規則變動四點並擴寫，新增五點：進站紀錄決定樣本起點、安全車只能近似排除、天氣為事後值且尚未取得、圈速特徵與分群標籤重疊、人工標記與編碼規則。

## 三、給 DE 的處理清單

2. FastF1：暫不下載。

**遇到這些情況怎麼處理**

| 情況 | 處理 |
| --- | --- |
| `duration` 出現「16:44.718」 | 用 `milliseconds`；超過 60,000 視為紅旗停車，算平均時排除 |
| q1/q2/q3 是「1:23.529」字串、空值 `\N` | 轉秒數；取最後一段有值的最佳圈 |
| 連 Q1 都沒成績（58 筆）或 `results` 有但 `qualifying` 沒有（20 筆） | 依 DA 的規則代入該場最大差距，加 `quali_missing` |
| `grid = 0`（82 筆） | 該場起跑人數 + 1，加 `pitlane_start` |
| 退賽者 `position` 為 `\N` | 歷史名次一律用 `positionOrder` |
| 單圈時間跨場比較 | 每場先排除第 1 圈、進站圈與下一圈（`pit_stops.csv` 的 `lap`）、慢於該車手該場中位數 10% 以上的圈；再算相對全場中位數的差距與相對自身中位數的標準差 |
| 輪胎衰退 | 用進站圈切 stint，每段內圈速對圈數跑簡單迴歸取斜率，整季平均後減隊友 |
| 退賽原因分類 | 非機械 = Collision、Accident、Collision damage、Spun off；機械 = Engine、Gearbox、Power Unit、Hydraulics、Brakes、Suspension、Electrical 等；不算退賽 = Finished、+N Laps；排除 Disqualified、Withdrew；「Retired」59 筆歸機械並標記 |
| 找隊友 | 同 `raceId`、同 `constructorId` 的另一位；只有 2 個場次隊不是剛好 2 人，記缺值 |
| 新人沒有前一季標籤 | `style_cluster_prev` 填「無前季資料」 |
| 2021 比利時站沒進站紀錄 | 進站次數記 0、進站時間缺值，不是資料缺漏 |

**第一階段輸出格式**：一筆 = 車手 × 賽季，欄位含 `driverId`、`year`、五組特徵、`style_cluster`。第二階段合併鍵 `driverId` + `year − 1`。
